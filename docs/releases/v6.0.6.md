Solus v6.0.6 expands local model imports, adds tools to compatible text and vision
chats, and improves document handling, thinking controls and runtime recovery.

**Requires Android 11/API 30 or newer and an ARM64-v8a device.** This raises the
minimum Android version from v6.0.0. Android 9/10 devices need an older compatible
release. Model weights are separate downloads, and memory requirements depend on
the selected export and context size.

## New in v6.0.6

- F-Droid builds use store-managed updates with a glass F-Droid control in Settings;
  the GitHub APK updater is disabled for that distribution. Official publication
  remains subject to F-Droid review.
- Completed LaTeX formulas render while a model is answering, in chat and vision responses.
- Escaped newlines before Markdown no longer appear as stray n characters.
- Incomplete formulas remain readable while streaming; code examples preserve literal escapes.
- Native builds use aligned Rust versions and normalized checkout paths. The official F-Droid candidate uses F-Droid's signing key; review and publication are pending.

## What's new

### Supported portable model pipelines

- ONNX Runtime, TensorFlow Lite and Candle/SafeTensors paths join the existing
  GGUF, LiteRT-LM and MediaPipe runtimes.
- Implemented adapters cover specific text-generation, classification,
  transcription, vision and SD1/SD2 diffusion contracts. Media paths remain
  experimental and CPU-based; this is not support for arbitrary checkpoints.
- Model admission uses configuration, graph interfaces, processing assets and
  required components rather than trusting a filename extension alone.
- LiteRT-LM remains pinned to **0.18.0**.

Read the [portable-model compatibility guide](https://github.com/ShounakPatra/Solus/blob/v6.0.6/docs/portable-models.md)
for architecture, tensor, cache and preprocessing requirements.

### More complete imports and Hugging Face browsing

- Browse HF repository, folder and file links and select multiple files using
  circular selectors.
- Required configuration, tokenizer, external-weight and shard companions are
  selected automatically at the resolved repository revision.
- Complete ZIP/`.solusmodel` imports preserve component folder structure.
- Earlier compatibility checks and clearer missing-file messages help identify
  incomplete or unsupported exports. Unsupported ONNX metadata is checked before
  scanning the remote graph.
- **Save files only** downloads repository files without registering them as a
  runnable model or claiming inference support.

### Tools and skills in the current chat

- Compatible LiteRT-LM and GGUF models can use calculator, date/time and document
  search tools; compatible LiteRT vision chats can use tools too.
- Tool and document-search changes apply to the next message in the current chat.
- Collapsible **Used tool** records show actual execution and are saved with chats.
- Additional skills cover hashes, unit conversion, text statistics, random
  selection, QR codes, Wikipedia, learning/adventure prompts, mood logs,
  reminders, calendar actions, maps, email drafts and custom prompt skills.
- Thinking can remain enabled with tool calling on. Available reasoning controls
  depend on the model, and not every response returns a separate thinking block.

Wikipedia and external services can use the network. Review calendar/email and
external-app actions before completing them.

### Documents and optional neural search

- Improved current-chat document scoping, explicit library selection, original-file
  previews and retained document handling.
- Sources identify retrieved passages; they do not verify every statement. Direct
  use of an attached document's text does not necessarily display a Sources chip.
- Optional **bge-small-en-v1.5** embeddings run offline after an approximately
  **33 MiB** download, with local fallback search and re-indexing support.
- Document-search model management is separate from the uploaded documents.
- Text-based PDFs and DOCX are supported; scanned/image-only PDFs require OCR.

### Runtime, interface and reliability improvements

- Optional warm-up moves some first-request setup into model preparation.
- Backend/thread tuning and more detailed latency diagnostics help distinguish
  loading, waiting, prompt processing and generation.
- Improved thinking configuration, reasoning-channel handling, GGUF progress
  labels, tool-round timeout recovery and cancellation paths.
- Repairs to document/library identities, history updates, deletion recovery,
  download publication/resume, tokenizer/EOS handling, audio decoding, generated
  image history and backup attachment handling.
- Updated glass controls and dialogs while retaining history search/pinning,
  temporary chats, profiles, memories and backups from earlier versions.
- Hugging Face tokens use Android Keystore-backed encryption and remain excluded
  from workspace backups. Compatible backup settings preserve unspecified values.

## 📲 Install or update

1. Download the **signed-release APK** from this release's Assets.
2. Allow installation from your browser or file manager if Android asks.
3. Install over your existing Solus app, then open Models and select a compatible
   downloaded model. First-time users need to download or import model weights.

Choose the **signed-release APK** in Assets, with its matching `.apk.sha256` file.
Do not use a debug or release-smoke APK as the production update. APK size, hash
and signing details belong to the exact uploaded artifact; values from v6.0.0
must not be reused.

Existing users can update without uninstalling when Android accepts the package
and signing identity. Back up important chats first. Backups exclude model weights,
access tokens and document indexes; source documents may need to be restored or
re-indexed separately.

Official F-Droid builds will use F-Droid's app signing key. GitHub APKs keep the
developer's signing key. Switching between these installations generally requires
backing up app data, uninstalling, and reinstalling from the chosen source.

Optional `bge-small-en-v1.5-int8.onnx` and `bge-small-en-v1.5-vocab.txt` assets provide
the pinned document-search download fallback. They are not chat models. Their
checksum and source/license notices accompany the mirror when provided.

## Compatibility and known limits

- Model architecture, quantization, operators, processor files, RAM and device
  drivers determine compatibility. A successful import or initialization does not
  prove output quality or acceptable speed on every phone.
- Raw TFLite exports without a supported task/processing contract, unsupported
  custom operations or external KV-cache interfaces need an appropriate packaged
  export or runtime adapter. Renaming a file does not add support.
- Tool calling remains model/template-dependent. Some exports ignore tool requests;
  check **Used tool** records rather than treating a plausible answer as execution.
  A large enabled skill set adds context and can cause long CPU prefill or a prompt
  timeout. Enable only the skills needed for the conversation.
- SafeTensors FP32 loading and complete diffusion/multimodal pipelines can need much
  more memory than their disk size. Experimental media paths are not a general
  promise of vision, speech or image-generation compatibility.
- Warm-up and GPU selection do not guarantee a faster first answer. Context length,
  new conversations, tool schemas, device memory and thermals affect latency.
- Host tests, lint, builds and instrumentation compilation do not establish physical
  compatibility with every model or replace smoke tests of the final signed APK.

Report issues with the installed version/code, exact export/revision, device,
runtime/backend, Think/tool settings and redacted logs.
