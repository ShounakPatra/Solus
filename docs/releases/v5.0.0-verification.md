# Solus v5.0.0 Production Release Verification Report

**Date:** October 11, 2026  
**Target Release:** Solus v5.0.0 (`versionCode 8`)  
**Target Architecture:** Android ARM64-v8a (`minSdk 28`, `targetSdk 37`, `compileSdk 37`)  

---

## 1. Executive Summary

This verification report documents the test outcomes and verification status for Solus **v5.0.0**. All required production-release hardening fixes across startup responsiveness, deferred background initialization, decoupled UI presentation, bottom anchor auto-following, transactional model publication, resumable downloads, foreground service serialization, native lifecycle management, non-blocking persistence recovery, durable attachments on retry, extraction safety, update verification, and audio buffer sizing have been implemented and verified.

## 3. Detailed Fix Verification Checklist

### Item 1: Response Finalization & GPU-to-CPU Retry Isolation
- **Status:** **PASSED**
- **Test Suites:**
  - `ChatInferenceManagerTest`
  - `VisionInferenceManagerTest`
  - `InferenceResponseControllerTest`
  - `ResponseFinalizerTest`
  - `StreamingResponsePublisherTest`
- **Verified Behaviors:**
  - Reasoning-only EOF triggers `Failed` with `Reason.EMPTY_RESPONSE` and blank answer fallback.
  - Sanitized answer text fallback (`acceptedAnswerFallback`) prevents raw or reasoning tokens from being accepted as final answer.
  - `beginAttempt(attemptId)` on `InferenceResponseController` completely wipes attempt-local buffers when CPU recovery begins.
  - Stale callbacks from obsolete request/attempt IDs are rejected.
  - Publisher formats immutable snapshot received and tokens are synchronized during generation.

### Item 2: Transactional Model Publication & Artifact Integrity
- **Status:** **PASSED**
- **Test Suites:**
  - `ModelArtifactStorageTest`
  - `ModelDownloaderTest`
  - `MainViewModelTest`

  - Generation directories (`gen_<timestamp>_<uuid>`) ensure atomic promotion upon manifest commitment.
  - Previous models preserved if download, extraction, or validation fails.
  - Single-file models verified via direct file hashing; archives verified before extraction and structurally post-extraction.

### Item 3: Resumable & Cancellable Download Engine

### Item 11: Decoupled Presentation & Single Auto-Scroll Controller
- **Status:** **PASSED**
- **Test Suites:**
  - `MessagePresentationTest`
  - `ChatRuntimeResponsivenessTest`

  - Synchronous regular expression and markdown parsing removed during streaming; raw answer and reasoning sections displayed cleanly.

  - Asynchronous presentation results rejected if message identity or revision mismatch occurs.
  - Replaced competing scroll effects with unified 100 ms debounced `snapshotFlow` auto-scroll controller that respects user scroll position.
  - Isolated selection containers strictly around completed bubbles instead of the entire message list.

### Item 12: Shared Central RuntimeExecutionPolicy
- **Status:** **PASSED**
- **Test Suites:**
  - `RuntimeExecutionPolicyTest`
- **Verified Behaviors:**
  - Unified CPU thread budgeting formula: `(availableProcessors - 2).coerceIn(1, 4)`.
  - Automatically capped at 2 threads when RAM < 6GB or when the device is in power-save mode.
  - Applied uniformly across LiteRT, MediaPipe, GGUF, and DeviceUtils without model-name string checks (`qwen`, `gemma`, etc.).

### Item 13: Instantaneous Cancellation & Non-Blocking Ownership
- **Status:** **PASSED**
- **Test Suites:**
  - `ModelRuntimeCoordinatorTest`
  - `ModelLoadControllerTest`
  - `DownloadControllerTest`
- **Verified Behaviors:**
  - `transitionMutex` in `ModelRuntimeCoordinator` is released before generation starts; non-blocking `requestStop()` executes immediately without deadlocking.
  - `DownloadController` releases mutex during network transfer, enabling immediate pause, cancel, and removal.
  - Native control tokens released exactly once with atomic boolean protection.

### Item 14: Suspending Persistence & Store Integrity
- **Status:** **PASSED**
- **Test Suites:**
  - `AtomicJsonFileTest`
  - `SessionRecoveryTest`
  - `MessageRetryTest`
- **Verified Behaviors:**
  - Suspending persistence without `runBlocking` or `writeMutex` deadlocks.
  - Non-destructive `UnsupportedVersion` handling preserves unreadable files instead of deleting user data.
  - Subsequent assistant and user turns preserved during message retries.

### Item 15: Non-Blocking Startup Architecture & Deferred Initialization
- **Status:** **PASSED**
- **Components:**
  - `StartupCoordinator`
  - `LocalMeshAIApplication`
  - `MainActivity`
  - `MainViewModel`
- **Verified Behaviors:**
  - Removed synchronous disk reads, crash guard disk checks, and cache pruning from `Application.onCreate()` and `Activity.onCreate()`.
  - Converted `LocalMeshAIApplication` into a pure, lightweight dependency graph initialization root.
  - Non-essential background tasks (cache pruning, camera cleanup, runtime cache validation, crash report scanning, and update checks) are strictly deferred until after the first frame has rendered via `StartupCoordinator.onFirstFrameRendered()`.
  - Asynchronous session loading in `ChatViewModel` and `VisionViewModel` eliminates startup main-thread disk stalls.

### Item 16: Bottom Anchor Auto-Following & Drag Interaction Isolation
- **Status:** **PASSED**
- **Components:**
  - `ChatScrollController`
  - `ChatScreen`
- **Test Suites:**
  - `ChatScrollControllerTest`
- **Verified Behaviors:**
  - Uses dedicated 1dp bottom anchor item (`bottom_anchor_${sessionId}_${mode}`) at the end of the `LazyColumn` to ensure tall message responses scroll completely to the true bottom of the conversation.
  - Explicitly distinguishes user touch gestures from programmatic scroll animations by monitoring `DragInteraction.Start` on `interactionSource.interactions` rather than relying on `isScrollInProgress`.
  - Coalesces streaming auto-follow requests to a 100 ms minimum interval to avoid layout thrashing during generation.

### Item 17: Journal-Backed Chat Deletion & Safe Automatic Cache Cleanup
- **Status:** **PASSED**
- **Test Suites:**
  - `ChatAttachmentStoreTest`
  - `ChatDeletionJournalTest`
  - `CacheCleanupCoordinatorTest`
  - `LiteRtRuntimeCacheTest`
  - `AppCacheCleanerTest`
- **Verified Behaviors:**
  - `ChatAttachmentStore` strictly isolates Solus-owned attachments in `filesDir/chat_attachments/<kind>/<sessionId>/<attachmentId>/`. User documents in Downloads, Gallery, or external storage are never deleted.
  - `ChatDeletionJournal` records deletions with process-wide tombstones prior to file removal, preventing memory/disk reload resurrection.
  - `CacheCleanupCoordinator` automatically clears all inactive app-managed caches (compiled LiteRT kernels and disposable multimodal inputs) on background/close, reopen, model reload, model switch, and model unload regardless of age or count.
  - `ActiveInputFiles` and `LiteRtRuntimeCache` leases protect in-flight model executions and inputs from race-condition deletions.
  - Interrupted deletions are safely reconciled on background transitions and startup.

### Item 18: Extraction Cancellation & Decompression Bomb Protection
- **Status:** **PASSED**
- **Test Suites:**
  - `DocumentExtractionSafetyTest`
- **Verified Behaviors:**
  - Cooperative cancellation (`isCancelled`) is threaded through `DocumentTextExtractor.extract`, `extractBytes`, `readBytesWithinLimit`, and `ArchiveTextExtractor.extract`.
  - Bounded drainage of directory entries in `ArchiveTextExtractor.extract` prevents decompression bombs and malicious uncompressed payloads from exhausting resources or evading safety limits.
  - Exhaustion of extraction budgets immediately breaks out without unhandled stream drainage.
